The problem.

An AI can be extremely capable and still know almost nothing about the person it is helping. Every assistant builds its own partial model of you — locked behind a provider's account, memory system, or chat history. Switching models can mean starting over.

Existing memory systems ask: “What should the AI remember about this user?”
HCP starts from the opposite question: “What does this human choose to make available to AI systems?”

That distinction is the foundation of the project.

The core model.

A portable, human-owned context layer — the Personal Codex — that can move between ChatGPT, Claude, Gemini, local models, agents, and future AI systems.

The first implementation is deliberately boring where it should be boring: Markdown for readability, YAML for structure, Git for history and rollback, JSON for machine interchange, local-first storage.

More than “memory”.

A Codex holds typed assertions — because “what is true”, “what I believe”, “what I prefer”, and “what an AI inferred” are not the same thing.

facts & identity

“I work primarily from Berlin.” Human-authored, authoritative.

beliefs, values, principles

“AI systems should preserve human agency.” Stated, not inferred.

preferences & boundaries

“I prefer direct, structured communication.” With explicit limits.

goals & observations

AI inferences stay proposed until a human reviews them.

The most important rule in HCP: an AI may propose an observation about a person. It may not silently redefine the person.

People change, so time is a first-class property: an old assertion is superseded by a current one, and Git preserves the history. The Codex becomes a versioned record of an evolving human point of view — not a static profile.

Selective disclosure.

A Codex can hold sensitive information. It should never be necessary to expose all of it to every AI system.

Context is organised into public, private, sensitive and restricted layers. Each AI receives a scoped Context Bundle: a restaurant assistant gets food and communication preferences; a career assistant gets professional identity and goals. Every bundle carries explicit trust conditions — no training, no resale, no profiling — and receivers must disclose honestly when they cannot honour them, instead of turning an incompatible covenant into false assurance.

Design principles.

  1. Human ownership
  2. Human readability
  3. Machine interoperability
  4. Explicit authority
  5. Temporal awareness
  6. Selective disclosure
  7. Privacy by architecture
  8. Provider independence
  9. Auditability
  10. Reversibility
  11. Extensibility
  12. No silent identity mutation

What HCP is not.

  • an AI model or chatbot
  • a proprietary memory database
  • a personality test or diagnosis
  • a digital clone
  • a social network
  • a blockchain requirement
  • a password manager
  • a place for keys, passwords or secrets

Current status.

Experimental / pre-alpha

HCP is a proposed protocol, not an established standard. This repository makes the idea concrete enough to implement, test, challenge, and improve. The initial target is a local-first CLI and library: create a Codex, validate it, track changes with Git, generate selective context bundles, import AI observations, and review them — with provenance and history preserved.

The long-term vision is a human context layer for the AI ecosystem: providers will keep competing on models, agents and products. Your context should not have to compete with them.
